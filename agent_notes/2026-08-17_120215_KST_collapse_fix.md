# Adversary directional collapse — mechanism, measurement, prototype fix

**Status:** mechanism VERIFIED numerically; tfjs-path prototype landed in this
worktree behind a default-off knob; fused WGSL port planned, NOT implemented.
**Supersedes the open hypothesis in**
`agent_notes/2026-08-06_214641_KST_angle_disc_diagonal_regression.md` — that
note's "pair frame makes a constant field hard to predict" guess is close to
the truth but the direction of the incentive is sharper and provable, and its
hypothesis 3 ("drive saturation") turns out to be the *point*-observer story
only.

## Goal

The adversarial pieces "pick a direction and get stuck": laminar streaks rather
than swirls, on the default piece (Adversary · Pair · HashGrid · Curl) and on
the user's hand-tuned point-observer dock state. Find the mechanism, measure it,
prototype the smallest principled fix.

## 1. What the generator actually maximizes (file:line evidence)

- `Adversary.payoff` — `src/core/gan/adversary.ts:1884`. One scalar:
  `Σ_j w_j · resid_j` with `w` = relaxed-WTA weights (`weightsWta`,
  `src/core/gan/adversary.ts:1382`).
- `Adversary.generatorLoss` — `src/core/gan/adversary.ts:1966`. For every loss
  except `angle-scale-hold` it is exactly `−mean(payoff)/scale`, and for
  `soft-angle` `scale = 1` (line 1969-1972). `energyAnchorLoss` returns
  **zero** for soft-angle (`lossNeedsEnergy`, line 784) — soft-angle is the one
  objective with **no magnitude anchor at all**.
- Composition into the field update: `adversaryGeneratorTerm`
  (`src/main.ts`, δ handler) added to `cfg.computeLoss` at ONE site inside
  `optimizer.minimize` in `tick`. Adversary pieces carry `ZERO_FIELD_LOSS`, so
  **the payoff is the only thing steering the field**.
- Both the D batch and the G batch are FRESH UNIFORM positions
  (`tf.randomUniform([sampleRate,2],0,1).mul(wh)`, `src/main.ts` ~2860 and
  ~2900). No advect coupling in the tfjs path — the collapse is not a particle
  clustering artifact.
- The default piece runs the **tfjs autograd adversary**, because
  `fusedAdvOk` refuses hashgrid fields (`src/main.ts:3350`,
  `advect.layout.encoding.kind !== "hashgrid"`).

## 2. The mechanism: the soft-angle embedding's NORTH POLE is a free lunch

Soft-angle residual (`softAngleResidual`, `src/core/gan/adversary.ts:699`;
`softSphericalEmbedding`, line 670):

```
ψτ(z) = (zx, zy, τ) / sqrt(‖z‖² + τ²)          resid = ‖ψτ(pred) − ψτ(y)‖
```

`ψτ(0) = (0,0,1)` — the **north pole**. Any prediction with `‖p‖ ≫ τ` lands on
the **equator**. Chord(pole, equator) = **√2 ≈ 1.4142**, and that is the same
√2 for *every* equatorial prediction: a ZERO target is maximally surprising to
every predictor that has not also collapsed its own output to ≈ 0.

Measured (real `softAngleResidual`, τ = 0.05, K = 4, ε = 0.05):

| target | E[relaxed-WTA payoff] |
|---|---|
| equatorial, direction uniform (a genuinely varied field) | **0.4413** |
| `y = 0` (north pole) | **1.3906** |
| ratio | **3.15×** |

`chord(pred, y=0)` for concrete predictions: 1.378 / 1.342 / 1.236 (→ √2 as
‖p‖ grows).

**So the generator's global optimum under soft-angle is to drive the ENCODED
TARGET to zero.** On the pair observer `y = [δ·ê∥, δ·ê⊥]`, `δ = F(x₂) − F(x₁)`
(`encodePairSignal`, `src/core/gan/adversary.ts:961`), so

> **target → 0  ⟺  F spatially CONSTANT  ⟺  laminar flow.**

This is not a gradient bug (the 2026-08-06 note verified fused-vs-tfjs
`cos = 1.0`) and no retune removes it: **the payoff's own maximum is the dead
field.** It is direction-only *asymptotically*, but ψτ also encodes magnitude in
the polar angle, and the generator found the polar axis.

### The POINT observer collapses by a different route

`PRESET=point` (the user's dock: point tuple, soft-angle τ=0.05, force target,
K=8, ε=0.22, weight 0.025, G lr 3.1e-4, D lr 1.2e-4, dualStd field):

```
step   R1      R2      |F|     DC      AC      sat    OW      Dloss
0      0.9604  0.8862  0.4963  0.4839  0.1896  0.000  0.8696  7.920e-1
200    0.9982  0.9986  0.9657  0.9654  0.1464  0.000  0.3863  5.368e-1
1100   0.4059  0.2104  0.5349  0.2921  0.4956  0.000 -0.8712  4.074e-1
2000   0.9542  0.8783  1.1793  1.1535  0.3572  0.460  0.2267  1.603e-1
```

Three separate facts, all measured:

1. **R1 = 0.96 AT INITIALIZATION.** A freshly-initialized dual [32,32] SELU+tanh
   field over the unit square is *already* almost perfectly laminar — a small
   MLP on a small input domain is dominated by its constant term. Nothing about
   the game causes that; it is the architecture. (The hashgrid field starts at
   R1 = 0.16, which is why the pair piece "looks good early".)
2. `y = F(x)` here, so the pole exploit would kill the art outright and D (which
   sees `x`) can chase it; the field instead **ratchets ‖F‖ upward**: at step
   2000, `|F| = 1.18` and **46 % of the domain has BOTH tanh components past
   0.9** (`sat = 0.460`). That is the 2026-08-06 note's "drive saturation"
   hypothesis, now measured. In saturation `∂F/∂preact ≈ 0`, so the generator's
   gradient vanishes and the picture literally **freezes** — "picks a direction
   and gets stuck".
3. Between steps 900 and 1400 R1 dips to 0.40 and OW to −0.87 (rotation
   dominated) before relocking. So on the point observer it is a **slow limit
   cycle with a long laminar dwell**, not a permanent attractor — one of the
   candidate explanations in the brief, confirmed. The very low D lr (1.2e-4)
   is what makes the dwell long.

## 3. The D-loss / G-residual chart duplication is REAL

The user's screenshot showing both at ~5.48e-1 is not a coincidence.

- **Fused path:** `src/render/webgpu/adversary_wgsl.ts:1486`
  `let sur = select(0.0, weighted, isFiniteF(weighted));` — `sur` **is**
  `weighted`. Finalize writes `stats[0] = sw/bf` (discLoss) and
  `stats[1] = ss/bf` (surprise) from those two accumulators
  (`adversary_wgsl.ts:1667-1668`, fed by `statW = weighted; statS = sur;` at
  1542-1543). The two HUD numbers are **bit-identical whenever the payoff is
  finite**, i.e. always in healthy operation.
- **tfjs path:** `predLoss = report.loss` = `Σ_j mean_B(w_j·d_j)` =
  `mean_B(Σ_j w_j d_j)` = `mean(payoff)` at the PRE-update heads
  (`trainStep`, `src/core/gan/adversary.ts:2029`); `surprise =
  mean(adv.surprise(s))` = `mean(payoff)` at the POST-update heads
  (`src/main.ts` ~1382). Same functional, one D Adam step apart.
- UI: `src/index.tsx:1693` plots `discHistory` (fed from `next.predLoss`, line
  995) and `src/index.tsx:1709` plots `genHistory` (fed from `next.surprise`,
  line 998).

It is not a mis-wired buffer — it is worse: the game **is** one zero-sum scalar
(that is stated deliberately in the `payoff` docstring), so two charts labelled
"D loss (minimize)" and "G residual (disagree maximizes)" can only ever draw the
same curve. **The HUD therefore contains no instrument that can show the game
separating, and none that would have shown this collapse.** Recommended fix:
keep one chart labelled "shared payoff (D minimizes · G maximizes)" and spend
the second row on the **polar order parameter R1** — the number this
investigation had to build a tool to see.

**Free tripwire, no new plumbing:** for any soft-angle piece, a payoff parked
near **√2 ≈ 1.414** means the encoded target has gone to zero, i.e. the field
is flat. It hit 1.362 at the baseline's step 800 and sat at 1.23–1.32 for a
thousand steps in the swirl-stacked run. Drawing that line on the existing
payoff chart costs nothing and names the failure on sight.

## 4. Measurement instrument

New: **`tools/collapse_probe.ts`** (bun + tfjs CPU). It reproduces the tfjs
oracle loop exactly as `tick` runs it for a standalone adversary piece
(uniform D batch → uniform G batch → Adam on the field only, ZERO field loss),
and reports on a fixed 64×64 grid:

- **R1** = `‖mean_i unit_τ(F_i)‖` — polar order, 0 = isotropic, 1 = laminar.
- **R2** = `‖mean_i e^{2iθ_i}‖` — nematic order; catches ± counter-streaming
  sheets that R1 cancels.
- **DC** = `‖mean F‖`, **AC** = `rms‖F − mean F‖` — the constant vs structured
  split. `AC → 0` is the collapse.
- **sat** — fraction of the domain with both tanh components past ±0.9.
- **rmsDiv / rmsCurl / rmsStrain** and the normalized Okubo–Weiss
  `OW = (⟨|S|²⟩−⟨ω²⟩)/(⟨|S|²⟩+⟨ω²⟩)`; OW < 0 ⇔ vortex-dominated.
  Jacobians are CENTRAL FINITE DIFFERENCES, deliberately — `forces()` is a
  plain forward pass (`src/core/field/helmholtz.ts`) and autograd-in-the-tape
  would be the second-order path that architecture exists to avoid.
- `IMG=<path.ppm>` dumps a hue = direction picture of the field. Needed because
  **headless Chrome on this box reports `adapter: null`** (verified against the
  live site with `tools/smoke.mjs`), so the live WebGPU page cannot be
  screenshotted here at all.

Knobs: `POLAR`, `NEMATIC`, `SWIRL`, `MAG`/`MAG_T`, `ANCHOR`/`ANCHOR_T`, `TAU`,
`WEIGHT`, `ARCH`, `SEED`.

1. **Candidate (a) exactly as briefed is insufficient.** `λ‖mean_B unit_τ(F)‖²`

   nothing about global alignment on its own. But the full stacked run shows
   the trap: it crushed ‖F‖ from 0.035 to **0.005** by step 1300, and while the
   field was that small the payoff sat at **1.23–1.32 ≈ √2** for a thousand

   and G was collecting the collapse bonus the whole time. It recovered after
   step 1400 (‖F‖ 0.039, payoff 0.62 at step 2000, AC 0.051 vs 0.157 for
   POLAR+NEMATIC alone), but the lesson stands: **any term that shrinks ‖F‖
   feeds the pole exploit.** If (b) is used at all it wants a much smaller λ
   and the two-sided rms‖y‖ anchor alongside it. The payoff trace is the
   tripwire — a D loss parked near 1.414 means the field has gone flat,
   whatever the direction metrics say.

**Caveat measured, not hypothesised:** the direction-order penalty has no
opinion about magnitude, and the pole exploit still pulls ‖y‖ down underneath
it — point `|F|` fell 0.36 → 0.080, pair settled at 0.105. Baseline `|F|` looks
larger (0.67 at step 1900) but that is 0.67 of pure DC, i.e. a dead constant.
If live particles read as sluggish, the pairing to reach for is direction-order
**plus** the two-sided `ANCHOR` on rms‖y‖ (which held `|F|` at 0.67/AC 0.21 in
its own run), not a bigger `drive`.

## 7. Fused WGSL plan (NOT implemented this pass)

The term is batch-coupled, which is the same shape the fused trainer already
solves for isotropy — copy that machinery exactly.

**Forward (pass A reduction).** Per sample accumulate four scalars beside the
existing covariance:

```
s  = sqrt(‖F‖² + τ²)          u = F / s
m1x += u.x        m1y += u.y
m2c += u.x²−u.y²  m2s += 2·u.x·u.y
```

Then `M = m/N` and `L = wP·(M1x²+M1y²) + wN·(M2c²+M2s²)`.

**Backward.** `dM` are constants on pass B, exactly like `dC`:

```
dM1x = 2·wP·M1x/N   dM1y = 2·wP·M1y/N
dM2c = 2·wN·M2c/N   dM2s = 2·wN·M2s/N
dL/du = (dM1x + 2·dM2c·u.x + 2·dM2s·u.y ,  dM1y − 2·dM2c·u.y + 2·dM2s·u.x)
dL/dF = (dL/du − u·(u · dL/du)) / s          // ∂u/∂F = (I − uuᵀ)/s
```

No extra field evaluations, no second-order terms — one reciprocal and one
projection per sample.

**Sites.**

1. `src/render/webgpu/train_wgsl.ts`
   - `FieldLossSpec` gains `W_POLAR`, `W_NEMATIC`, `POLAR_TAU` (default 0/0,
     same shape as `W_COVER`/`W_CENTER`, `train_wgsl.ts:83-106`).
   - compile-time gate `const usePolar = loss.W_POLAR !== 0 || loss.W_NEMATIC
     !== 0;` next to `useIso` (`train_wgsl.ts:729`).
   - extend the pass-A partial reduction that already carries the covariance
     (`train_wgsl.ts:963`, `lossOut[0] = red[0].w/nf + W_ISO*Liso`) with the
     four moments — the existing fold is a vec4, so this needs a second vec4
     lane or a second reduction pass.
   - add the seed next to the isotropy seed at `train_wgsl.ts:1126-1127`
     (`dFs.x += ...`, `dFs.y += ...`).
2. `src/render/webgpu/ad/losses.ts`
   - `directionOrderTerm(g, M1x, M1y, M2c, M2s)` beside `isotropyTerm` (line
     54) — the IR twin of the forward.
   - `directionOrderFold(g, Fs, dM, tau)` beside `isotropyFold` (line 618) —
     the local per-sample fold whose `∂/∂F` reproduces the seed, i.e. the same
     "batch-coupled term becomes autodiff-able" trick.
3. `src/main.ts` — drop the `pressureTag === "none"` clause from `fusedAdvOk`
   and instead map `GamePressure` → `W_POLAR/W_NEMATIC/POLAR_TAU` in the
   `FieldLossSpec` handed to `FusedTrainer`.
   **Authority check required, not optional:** pass B computes
   `g = fieldLossGrad + extGrad` and hands the sum to one Adam. Adversary
   pieces carry `ZERO_FIELD_LOSS` precisely so the critic owns the whole
   update; this is the first legitimate exception, so measure `‖fieldLossGrad‖`
   vs `‖extGrad‖` with `tools/pixel_disc_authority_probe.ts` before shipping and
   record the ratio. If the pressure ends up at 99 % of `‖g‖` the artwork is
   the penalty, not the game.

**Parity fixture — `tools/train_wta_test.ts`.** New section modelled on the
existing W_ISO gate:

- fixed B = 64 batch, `W_POLAR=0.05 W_NEMATIC=0.05 POLAR_TAU=0.05`, every other
  weight 0;
- assert forward: `lossOut[0]` vs `directionOrderLoss(field.forces(pos), …)`,
  relative error ≤ 1e-5;
- assert backward: `FusedTrainer.readGrads()` vs `tf.variableGrads` of the same
  scalar — `cos ≥ 1 − 1e-6` and relative ‖·‖ error ≤ 1e-4, the gate the file
  already uses for the soft-angle disc/gen grads;
- degenerate guard: an all-zero force batch must give **exactly** 0 loss and a
  finite (zero) gradient. That is the τ softener's entire job and it is the one
  input this term will actually see if the collapse happens again.

   measured here: (i) give `soft-angle` the two-sided energy anchor that
   `angle-relative-scale` already has (`energyAnchorLoss`,
   `src/core/gan/adversary.ts:880`) but anchored on **‖y‖**, not on
   `tupleEnergy` — `tupleEnergy` is the mean member-signal norm and does NOT go
   to zero when the field goes constant, so it would miss this exactly;
   (ii) raise the default τ. The `TAU=0.5` control removed the collapse
   completely, but it also pushed `|F|` to 1.0 (the amplitude cheat the piece
   comment warns about) — τ is a real dial with a real trade and deserves its
   own sweep.
2. **λ was not tuned.** 0.05 was the first value tried for both weights and it
   worked on both presets; no sweep was run, and the two weights were never
   varied independently.
3. **No live soak.** Headless Chrome here has no WebGPU adapter, so the visual
   A/B is the probe's own direction-field render, not the real artwork. Someone
   on a machine with an adapter should run
   `node tools/soak_adversary.mjs` with and without `?advPolar=0.05&advNematic=0.05`
   and confirm it reads as swirls.
4. **The point preset's laminar init is untouched by any of this.** R1 = 0.96
   before a single training step is an architecture fact about small MLPs on
   the unit square; the pressure fixes it within ~100 steps, but a better init
   (or a Fourier/hashgrid encoding, which starts at R1 = 0.16) would start the
   piece in a better place.
5. **HUD.** Replace the duplicated G-residual chart with R1 (§3). Cheap on the
   fused path — it is four more scalars in a reduction that already exists.
